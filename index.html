CMMI

Modelo CMMI en el Desarrollo de Software

Capability Maturity Model Integration (CMMI). Modelo de buenas prácticas gestionado por ISACA para planificar, desarrollar, entregar y mantener software con procesos estandarizados, medibles y enfocados en la calidad.

Pilares y Conceptos de CMMI

Gestión de Requisitos

Asegura que las necesidades del usuario estén documentadas, priorizadas, aprobadas y conectadas mediante trazabilidad directa con el código y las pruebas.

Control y Gestión de Riesgos

Identifica situaciones inciertas a tiempo, estima su probabilidad e impacto, asigna responsables y define respuestas oportunas para proteger el proyecto.

Aseguramiento de Calidad - QA

Comprueba mediante revisiones, auditorías y pruebas continuas que se utilicen los procesos adecuados para prevenir defectos y garantizar entregas confiables.

¿Quién lo creó?

CMMI se originó en el Software Engineering Institute (SEI) de la Carnegie Mellon University y actualmente es administrado por ISACA a través del CMMI Institute.

Niveles de Madurez
  • Nivel 0: Incompleto
  • Nivel 1: Inicial / Reactivo
  • Nivel 2: Gestionado
  • Nivel 3: Definido
  • Nivel 4: Cuantitativo
  • Nivel 5: Optimizado para la mejora continua

Ventajas y Desventajs de CMMI

VENTAJAS

  • Mayor consistencia
  • Visibilidad de riesgos
  • Control temprano
  • Decisiones con datos

DESVENTAJAS

  • Exige recursos y tiempo
  • Riesgo de proceso pesado
  • Depende de la cultura
  • Requiere compromiso real
